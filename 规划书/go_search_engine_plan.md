# 维空 voidxo — Go 后端搜索引擎方案（v2.1，基于原规划书修订）

> **项目名称：voidxo（中文：维空）**——工作目录 `D:\project\voidxo`，取代原方案代号 OpenTrace。
> 前置文档：`参考/规划书/search_engine_startup_plan.md`（OpenTrace 方案）
> 参考实现：`参考/以前的项目/sese-engine-slave`（Python 爬虫+索引）、`owlquery-search`（前端）
> v2 修订点：① 后端技术栈从 Python 换成 **Go**；② 补充「AI 时代 vs 谷歌/百度」的差异化打法；③ 复用 sese-engine 已验证的爬虫/排序算法设计。
> v2.1 修订点：④ 新增**标签过滤**（no ai / no 广告 / no 个人 / no 平台）与**时间过滤**（1天/3天/1周/1月）；⑤ 爬取策略从开放 BFS 改为**白名单策展**（管理员提交 + 用户提交审核 + 黑名单）；⑥ 前端定栈 **React 18 + Material UI**，主色基调 `#F8F8F0`，构建产物 `embed.FS` 打进 Go 单二进制。

## 一、先回答核心问题：谷歌/百度 + AI 时代，凭什么突围

### 大厂的结构性盲区（它们做不了或不愿做的）

| 盲区 | 谷歌/百度的现状 | 我们的机会 |
|---|---|---|
| **商业模式冲突** | 广告收入依赖点击与停留，AI 摘要正在吃掉自家广告位 | 无广告排序，排名只由质量决定 |
| **SEO 垃圾内容** | CSDN 采集站、AI 农场文大量占据中文搜索结果 | 域名级质量分 + AI 生成内容检测降权 |
| **长尾内容消失** | 独立博客、小站点因权重低被埋到 10 页之后 | 「发现模式」主动打捞高质量冷门内容 |
| **黑箱排序** | 排序理由不可知，结果不可复核 | 每条结果给出可解释排序理由 |
| **AI 幻觉** | AI 摘要无来源或来源错误，用户无法验证 | 证据优先：AI 只做摘要，每条结论必须挂原文引用 |
| **隐私** | 行为追踪、画像投放 | 不追踪、无画像，搜索即匿名 |
| **可自托管** | 闭源 SaaS，数据不出门不可能 | Go 单二进制 + 内嵌索引，一条命令私有部署 |

### 一句话定位

> **谷歌/百度给你"流量答案"，AI 给你"生成的答案"，我们给你"可验证的证据"——并且能找到它们都找不到的内容。**

差异化不是"比谷歌搜得更全"（不可能），而是在**一个垂直领域内做到：更准、可解释、可追溯、无垃圾、可私有部署**。

## 二、产品特色功能（六大支柱）

### 功能 A：技术问题专搜（基本盘，沿用原方案）
- 错误日志、API 名、版本号、代码标识符精确匹配优先。
- 语义相似度永远不得压过精确匹配（原方案已有，保留）。

### 功能 B：可解释排序（差异点 1）
每条结果附带「为什么排在这里」标签：
- ✅ 精确匹配报错文本
- ✅ 来自 v2.x 官方文档
- ✅ 反向链接繁荣度 Top 5%（复用 sese-engine 繁荣度算法）
- ⚠️ 内容与 N 个页面重复，已聚合

### 功能 C：发现模式（差异点 2，对抗信息茧房）
结果页分两个区：
- **主结果**：高权重答案（对标谷歌前 10 条质量）
- **深网发现**：独立博客、小开源项目、冷门讨论——用繁荣度算法的**倒数**打捞：内容质量高但反向链接少的页面

sese-engine 的繁荣度算法天然支持这个：正着用是排序，反着用是发现。

### 功能 D：AI 时代生存位——证据链摘要（差异点 3）
- AI 摘要不是替代搜索，而是**索引之上的一层可选视图**，默认折叠。
- 每条 AI 结论强制挂引用编号，点击跳转原文段落高亮。
- 无引用来源的结论标记为「未验证」。
- 检索层找不到正确原文时，宁可显示「未找到可靠来源」也不硬编。

### 功能 E：中文技术内容质量护城河（差异点 4）
针对中文搜索痛点（百度的主场，也是最烂的场）：
- 采集站指纹库：识别 CSDN 采集、简书转载、AI 农场文的模板特征（sese-engine 已有 `结构` 模板字段，可直接扩展）
- 源头追溯：同一内容自动聚合到最早/最权威来源，转载一律降权
- 时间衰减：过时教程（如 PHP 5 时代的答案）按版本相关性降权

### 功能 F：单二进制自托管（差异点 5，Go 独有优势）
Python 方案做不到的：
- `voidxo.exe` 单文件 = 爬虫 + 索引 + 搜索 API + 前端静态资源
- SQLite/Pebble 嵌入式存储，零外部依赖
- 企业买去做**私有文档搜索**（内网 Confluence/GitLab/代码库），这是商业模式第三阶段的核心卖点
- 与你现有的 PHP 产品（Halou-Chat、Owlsgo 论坛）可以形成「站内搜索插件」联动

### 功能 G：标签过滤（内容成分开关）

结果页提供一组**排除型标签开关**，用户一键过滤掉不想要的内容成分：

| 开关 | 含义 | 判定方式 |
|---|---|---|
| `no ai` | 排除 AI 生成内容 | AI 文本检测器（困惑度/突发度特征）+ 已知 AI 农场域名黑名单 + 页面自声明 meta |
| `no 广告` | 排除广告泛滥页 | 正文/广告 DOM 占比阈值、弹窗与联盟链接计数（正文提取阶段打标） |
| `no 个人` | 排除个人博客/个人站 | 备案类型 + 域名元数据 + 站长提交时的分类自声明（见后台审核） |
| `no 平台` | 排除 UGC 平台（CSDN/知乎/简书等） | 平台域名清单，与功能 E 的采集站指纹库共用数据 |

实现要点：
- 标签在**索引时预计算**，写入文档的 `labels` 字段（如 `["ai_suspect","ugc_platform"]`），查询期只做过滤，零额外延迟。
- 标签是**概率性判定**，结果页对被打标的页面展示标签徽章（可解释排序的延伸），用户可对误判一键反馈——反馈数据回流训练规则，这是相关性评估数据之外的第二类自有资产。
- 默认全开/全关由用户在设置页持久化（localStorage + 登录后同步）。

### 功能 H：时间过滤

结果页时间筛选：**一天内 / 3 天内 / 一周内 / 一个月内 / 全部**。

- 依赖索引字段 `published_at`（正文提取时解析）与 `fetched_at`（抓取时间）双时间戳。
- `published_at` 缺失时降级用 `fetched_at`，并在结果上标记「按收录时间」。
- 与功能 A 联动：搜「报错/版本兼容」类查询时时间过滤器权重提示更高（如「该问题近 30 天有新讨论」）。
- 时效性排序分 `R`（第四节公式 w4）与时间过滤是两个独立机制：过滤是硬条件，时效分是软排序。

### 功能 I：策展白名单索引 + 站长后台（差异化战略级功能）

**核心策略转变：从开放 BFS 改为「白名单策展爬取」。** 引擎只爬白名单内的网站——这直接把"索引质量"从算法问题变成运营资产，也是对抗 SEO 垃圾的终极手段（垃圾站根本进不了索引）。

数据流：

```text
用户提交网站 ──→ 审核队列 ──→ 管理员审核 ─┬─ 通过 → 白名单 → 爬虫种子队列
                                          └─ 拒绝 → 黑名单（永不抓取）
管理员直接提交 ──────────────→ 白名单
```

后台页面（管理员）：
- **网站提交**：管理员直接添加站点进白名单（含分类：官方文档/开源项目/个人博客/平台/媒体，供 `no 个人`/`no 平台` 标签复用）。
- **审核队列**：用户提交的站点列表，展示自动预检结果（可达性、robots 是否允许、内容类型初判、是否在黑名单历史），一键通过/拒绝。
- **白名单管理**：启用/禁用、分类编辑、抓取频率设置、最后抓取状态与错误日志。
- **黑名单管理**：添加/移除、命中统计（用户提交被拒次数、爬取被拦截次数）。
- 风格沿用你的后台规范：统一搜索栏 + 多选框 + 批量操作 + 分页；弹窗禁浏览器原生 dialog（MUI 用 `Dialog` 组件天然满足）。

用户侧：
- 搜索结果页/404 无结果页放「提交网站」入口，表单字段：URL + 分类 + 一句话理由。
- 提交后显示审核状态（待审/已收录/已拒绝），不做邮件通知（MVP 阶段）。

## 三、Go 技术架构（替代原 Python 方案）

```text
数据源（白名单策展）
  ├─ 管理员提交 ──┐
  ├─ 用户提交 → 审核队列 → 白名单表 ──┐
  └─ 黑名单表（拦截层）                │
       ↓                              ↓
┌─ 抓取层 (Go) ─────────────────────────────┐
│ colly/自研爬虫（种子 = 白名单站点）          │
│ ├─ robots.txt 检查 (temoto/robotstxt)      │
│ ├─ 白名单内 BFS 扩展 + 队列加权丢弃         │
│ │  （出链仅在同站/同白名单域名内跟进）       │
│ └─ 限流 + 重定向表                         │
└───────────────────────────────────────────┘
       ↓
┌─ 处理层 (Go) ─────────────────────────────┐
│ goquery/go-readability 正文提取             │
│ ├─ simhash 去重 + 内容指纹                  │
│ ├─ jieba/gse 中文分词                      │
│ ├─ 反向链接统计器（URL 前缀树, 定时任务）    │
│ └─ 标签分类器：ai_suspect / ad_heavy /     │
│    personal / ugc_platform → labels 字段   │
└───────────────────────────────────────────┘
       ↓
┌─ 存储与索引 ──────────────────────────────┐
│ 元数据: SQLite（文档/白名单/黑名单/审核队列）│
│ 全文索引: Bleve (纯 Go 内嵌) 或 OpenSearch  │
│   字段: title/body/labels/published_at/    │
│         fetched_at/prosperity/domain       │
│ KV: Pebble (替代 sese-engine 文件存储)      │
└───────────────────────────────────────────┘
       ↓
┌─ 检索与排序 API (Go, chi) ────────────────┐
│ BM25 + 字段权重 + 繁荣度 + 时效性           │
│ 硬过滤: labels 排除 + 时间窗 + 域名去重     │
│ 采集站降权 + RRF 融合                      │
│ 管理 API: /admin/sites /admin/review       │
│           /admin/whitelist /admin/blacklist│
└───────────────────────────────────────────┘
       ↓
前端（React 18 + Material UI，构建产物 embed.FS 打进二进制）
  ├─ 搜索首页 / 结果页（标签开关 + 时间筛选器）
  ├─ 主结果 / 深网发现 双区 + 排序理由标签
  ├─ 设置页（默认过滤偏好持久化）
  └─ 管理后台（网站提交/审核队列/白名单/黑名单）
```

### Go 技术栈对照表（替代原规划书第四节）

| 模块 | 原方案 (Python) | Go 版方案 | 理由 |
|---|---|---|---|
| 后端 API | FastAPI | **chi / fiber + net/http** | 单二进制，P95 延迟更低 |
| 爬虫 | Scrapy | **colly**（种子=白名单，参考 `虫.py` 的 BFS/限流） | goroutine 天然适合并发抓取；白名单策略使全网 BFS 队列裁剪不再是核心问题 |
| robots.txt | reppy | **temoto/robotstxt-go** | 谷歌官方解析器的 Go 移植 |
| 正文提取 | Trafilatura | **go-readability / goquery** | 够用；噪声规则需自己调 |
| 中文分词 | jieba (py) | **gojieba / gse / sego** | 技术搜索需自定义词典（API 名、框架名） |
| 搜索引擎 | OpenSearch | **第一阶段 Bleve（纯 Go 内嵌），规模上来后再迁 OpenSearch** | 10 万文档 Bleve 足够；过早引入 ES 是运维负担 |
| 元数据 | PostgreSQL | **SQLite（WAL 模式）** | 单机 MVP 零运维；月活上万再迁 PG |
| KV 存储 | 文件系统 | **Pebble / BadgerDB** | 对应 sese-engine 的「本地存储」组件 |
| 去重 | — | **simhash（自研 200 行）** | 内容指纹 |
| 前端 | Next.js | **React 18 + Material UI (MUI v6)**，Vite 构建，产物 `embed.FS` 打进 Go binary | 后台/筛选组件密度高，MUI 组件库省自研；单二进制部署不变 |
| UI 主题 | — | **主色基调 `#F8F8F0`**（米白背景），MUI `ThemeProvider` 定制 | 见下方主题片段 |
| 部署 | Docker + VPS | **单二进制 / 可选 Docker** | 自托管卖点 |
| 监控 | — | **Prometheus**（sese-engine 已有打点，直接复刻） | 爬虫吞吐、索引延迟、QPS |

### MUI 主题基调（`#F8F8F0`）

`#F8F8F0` 是米白近白色，适合作为全局背景基调而非主按钮色（对比度不足）。主题定义：

```ts
// theme.ts
import { createTheme } from '@mui/material/styles';

export const theme = createTheme({
  palette: {
    background: {
      default: '#F8F8F0',   // 全局米白背景
      paper: '#FFFFFF',     // 卡片/结果条用纯白浮起
    },
    primary:   { main: '#2F4F4F' },  // 深灰绿，与米白对比度 9.4:1（AAA）
    secondary: { main: '#8B7355' },  // 暖棕，用于标签徽章
    error:     { main: '#C0392B' },
    text:      { primary: '#1A1A1A', secondary: '#5A5A50' },
  },
  shape: { borderRadius: 8 },
  typography: {
    fontFamily: '"Inter", "Noto Sans SC", "PingFang SC", sans-serif',
  },
  components: {
    MuiChip: { defaultProps: { size: 'small' } },  // 标签开关用 Chip
  },
});
```

页面骨架（MUI 组件映射）：

| 页面 | 关键 MUI 组件 |
|---|---|
| 搜索首页 | `Container` + `TextField`（搜索框）+ 品牌区 |
| 结果页 | `Drawer`/`Stack` 侧栏放标签开关（`ToggleButtonGroup`/`Chip`）；`Tabs` 放时间筛选（一天/3天/一周/一月/全部）；结果条用 `Card` + 标签徽章 `Chip` |
| 设置页 | `FormControlLabel` + `Switch` 持久化过滤偏好 |
| 管理后台 | `DataGrid`（白名单/黑名单/审核队列，自带搜索/多选/分页）+ `Dialog`（确认弹窗，满足"禁原生 dialog"规范） |

OwlQuery 旧前端（Tailwind 静态页）不再沿用，仅保留其交互设计稿（`owlquery-search.design`）作为页面流转参考。

### 从 sese-engine 直接继承的算法资产

| 旧实现 | 文件 | 价值 | Go 化成本 |
|---|---|---|---|
| BFS 队列加权丢弃 | `虫.py` | 防内存爆、优先抓高质量域名 | 低（核心逻辑 ~100 行） |
| 反向索引筛选规则 | `文.py`/`上网.py` | http/https 合并、域名多样性裁剪 | 低 |
| 繁荣度 URL 前缀树 | `分析.py` | 4G 内存估算无限 URL 的 PageRank 近似 | 中（树结构 + 内存阈值切换策略） |
| 编码硬解码策略 | `虫.py::_解析文本` | utf8→gbk 兜底，中文站必备 | 低 |
| 模板指纹字段 | `回.py`（`结构`字段） | 采集站识别的基础 | 低 |

## 四、排序公式（沿用原方案，补充繁荣度）

```
S(q,d) = w1·BM25 + w2·精确匹配 + w3·繁荣度 + w4·时效性 + w5·质量分 - p1·采集站惩罚 - p2·重复惩罚
```

相比原方案的改动：
- **w3 繁荣度**不再是隐性的，用 sese-engine 的反链统计器显式计算——这是我们的独有信号，谷歌的 PageRank 对我们透明，我们的繁荣度对小站长可解释。
- **p1 采集站惩罚**是中文搜索的关键差异项。
- 权重仍为实验参数，评估方法沿用原方案第九节（Recall@20 / NDCG@10 / MRR / 无结果率 / P95）。

## 五、MVP 范围修订

原方案 MVP 范围不变（20–50 站点、1–10 万文档），技术栈换成 Go 后的调整：

### 必须完成
- [ ] Go 爬虫（robots + 限流，**种子=白名单**，域内 BFS 扩展）
- [ ] 白名单/黑名单/审核队列数据表 + 管理后台 4 页（提交/审核/白名单/黑名单）
- [ ] 用户侧「提交网站」表单与审核状态查询
- [ ] 正文提取 + simhash 去重 + 中文分词
- [ ] **标签分类器**：`ai_suspect` / `ad_heavy` / `personal` / `ugc_platform` 索引期打标
- [ ] SQLite 元数据 + Bleve 全文索引（含 `labels` / `published_at` / `fetched_at` 字段）
- [ ] BM25 + 字段权重 + 繁荣度排序 API（支持 labels 排除过滤 + 时间窗过滤）
- [ ] React + MUI 结果页：标签开关（no ai / no 广告 / no 个人 / no 平台）+ 时间筛选（1天/3天/1周/1月/全部）+ 排序理由标签
- [ ] 100 条测试查询集 + 人工标注
- [ ] Prometheus 打点

### 验证有效后再做（与原方案一致）
- 向量语义检索（Go 可调 ollama/外部 embedding API，索引用 hnsw）
- 证据链 AI 摘要
- 采集站指纹库（需积累样本后训练/规则化）
- 自托管企业版打包

### 关键决策（原方案遗留问题，现在给结论）
> **中文 vs 英文？** → **中文技术内容优先**。
> 理由：① 中文搜索体验被百度做烂的程度远大于谷歌，用户痛感强、竞品弱；② 你熟悉中文开发者社区，有直接触达渠道（论坛、聊天产品用户）；③ 英文赛道有 Kagi/Marginalia 等强敌，中文垂直赛道几乎是空白。

## 六、商业模式（补充 Go 自托管路线）

| 阶段 | 原方案 | Go 版补充 |
|---|---|---|
| 1 免费验证 | 公开搜索站 | 不变 |

## 八、风险与红线（沿用 + 补充）

1. **不要从零写倒排索引**（原方案红线，保留）——Bleve 够用就用 Bleve。
2. **不做全网抓取**——预算红线不变：未验证质量前不买 GPU、不搭集群。
3. **AI 摘要后置**——检索层没有正确原文，摘要再好也是幻觉放大器。
4. Go 版新增风险：**Bleve 在千万级文档时性能下降明显**，需在 50 万文档规模做一次压测，决定是否提前迁 OpenSearch。
5. Go 中文分词生态弱于 Python（jieba 移植版质量参差），技术符号（`kubernetes.io`, `v1.28`）需要自定义分词规则，第 3–4 周预留时间。
6. **白名单策展的冷启动悖论**：索引质量靠策展，但覆盖度取决于运营投入。红线：首批 20–50 站跑通质量验证前，不开放用户提交入口——避免审核队列成为第一个烂尾功能。
7. **`ai_suspect` 标签误判风险**：AI 检测本身准确率有限，误判会伤害独立作者。红线：该标签只做过滤开关，**不做排序降权**，且结果页必须展示「为什么被打标」+ 误判反馈入口。
8. **时间过滤的数据质量**：大量页面无可靠 `published_at`，降级到 `fetched_at` 会让「一天内」结果偏少——属预期行为，不要为了让数字好看而放宽口径。
